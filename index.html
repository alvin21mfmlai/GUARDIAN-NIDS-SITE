01 — Overview

One pipeline, six benchmarks, one honest comparison

Supervised NIDS evaluation is easy to get wrong. Benchmarks differ in traffic era, feature construction, label taxonomy and class balance, and a classifier can score well for the wrong reason — memorising a lab identifier, exploiting duplicated rows, or simply predicting the dominant class. GUARDIAN-NIDS is the apparatus built to remove those confounds: every dataset flows through the same four-stage, YAML-driven pipeline, every model sees an identical frozen feature matrix, and every number traces back to a single tidy evidence file.

Leakage-safe by construction

IP addresses, ports, flow IDs and timestamps are dropped at load. Raw label columns never survive as features. Every fitted statistic — medians, scalers, one-hot vocabularies, MI rankings, class weights — comes from the training partition only and is frozen into a human-readable schema.json.

Balanced metrics, not headline accuracy

Macro-F1 is the primary metric, computed in pure NumPy and cross-checked against scikit-learn to 1e-9. Accuracy, weighted-F1, ROC-AUC, PR-AUC, per-class recall and confusion matrices sit alongside it — because a detector that is 93.4% accurate can still score 0.256 macro-F1.

Config-driven, not code-driven

Adding a dataset or a model means editing a YAML file, not the pipeline. Dataset-specific quirks — embedded header rows, Infinity cells, label-spelling drift, encoding faults — are declared in datasets.yaml and isolated behind adapters.

From-scratch deployment path

The winning standalone algorithm — Random Forest — is re-implemented with NumPy alone: CART/Gini trees, bootstrap sampling, per-node √p feature subsampling, balanced-subsample weighting and soft-vote aggregation, persisted as .npz arrays plus JSON. No pickle, no ML library on the prediction path.

Reproducible end to end

A single seed (42) governs splits, sampling, tuning, initialisation and ensemble construction. Every results row records its seed, sample caps, solver substitutions and parameter provenance, and a deterministic report generator validates the evidence file before any table or figure is drawn.

Tested on synthetic fixtures

Around 30 tests cover the cleaning quirks each dataset exhibits, split stratification, schema JSON round-trips, no-leakage guarantees, unseen-category handling, metric equivalence, ensembles and per-model caps — all without needing a single byte of real benchmark data.

Two winners, two questions. The Stacked-LR ensemble is the strongest aggregate predictive system (mean test macro-F1 0.824), but it is a composite of seven base estimators plus a meta-learner. The library Random Forest is the strongest single deployable algorithm (0.818 test, 0.867 validation, winning 11 of 12 validation cases) — and is therefore the algorithm re-implemented from scratch.
02 — Architecture

Four stages, each independently testable

Each stage has its own CLI, its own artefacts and its own tests. Stage 4 reuses the Stage 2 preprocessing contract but trains, stores and executes the selected Random Forest without any ML estimator library — so the deployment path is provably independent of scikit-learn.

1

Ingest & cleanse

run_pipeline.py

Reads published engineered CSV/Parquet tables — never packet captures — in 250,000-row chunks. Normalises column names, strips embedded repeated header rows, coerces numerics when ≥95% of non-missing values parse, replaces ±Infinity with missing, normalises label spellings per source, and validates required columns and label domains. Unknown labels raise rather than being silently mapped to benign. Duplicates are reported here, never removed globally.

interim/<ds>/<split>.parquet reports/<ds>/data_quality.json
2

Freeze the preprocessing contract

run_preprocess.py

Establishes partitions (official splits preserved; 15% validation carved from train; otherwise a seeded stratified 70/15/15), removes exact duplicates from training only, then fits median imputation, near-constant and correlation pruning, standardisation and one-hot encoding on the training rows alone. Rare categories and unseen test categories both land in a shared __OTHER__ bucket so the feature dimension can never shift at inference. Mutual-information rankings and balanced class weights are computed and frozen alongside.

processed/<ds>/schema.json processed/<ds>/splits.npz reports/<ds>/preprocess_report.json
3

Train & evaluate the candidate suite

run_models.py

Seven base learners and two score-level ensembles are fitted on the identical frozen matrix, for both the binary and the native multi-class task. Large-scale solver substitutions (SGD hinge / SGD log-loss above 500k training rows) and per-model caps (FT-Transformer at 500k stratified rows) are declared in config and recorded in the result metadata. One tidy row is appended per evaluated split.

results/results.csv reports/<ds>/models_<task>.json
4

Library-free training & deployment

run_deploy.py

Trains RandomForestScratch on the same frozen matrix and packages it with the Stage 2 schema into a self-contained bundle. A newly supplied raw benchmark file can be cleaned by the same adapter, transformed by the same frozen schema and classified with nothing but NumPy and pandas on the path — which is what prevents training/serving skew. A compare subcommand benchmarks it against scikit-learn under aligned hyperparameters.

deploy/<ds>_<task>/schema.json model.npz + model.json bundle.json predictions_*.csv
Why the sequence matters. The scratch target is chosen from validation macro-F1 across the seven standalone algorithms — before the untouched standard-test partitions are read. Algorithm selection is therefore independent of both the final test outcome and the deployment implementation.
03 — Benchmarks

Six datasets, deliberately not interchangeable

One historical baseline, two modern enterprise corpora, and three standardised NetFlow-v2 derivatives. The portfolio spans traffic era, attack taxonomy, feature construction, scale and class imbalance. Original and derivative representations are never pooled into a shared split — agreement between them indicates robustness to feature engineering, not cross-network generalisation.

Classification scope

  • Binary. Every recognised attack label maps to 1, benign to 0. Unknown, unlabelled or malformed values raise a validation error rather than defaulting to benign.
  • Native multi-class. Each benchmark keeps its own security taxonomy — NSL-KDD collapsed to its five macro-classes, UNSW-NB15 as Normal plus nine attack categories, CIC and NF-v2 members on their normalised source labels.
  • No universal label map is imposed. A CIC web attack and a UNSW exploit may be related, but treating them as identical without a documented ontology would amount to subjective re-labelling.

04 — Method

The controls that make the comparison mean something

The final benchmark is a fixed-configuration comparison: reference hyperparameters are declared in config before any test evaluation, so the numbers describe one controlled model suite rather than the maximum attainable score of every algorithm on every dataset.

Leakage controls

  • Source and destination IP addresses, flow identifiers and exact timestamps are excluded before feature transformation; NF-v2 address and port fields are excluded consistently.
  • Raw label-source columns (label, attack_cat, type, difficulty) are dropped at load, with a config-level safety net behind them.
  • All fitted statistics — medians, category vocabularies, scale parameters, correlation and near-constant decisions, MI scores, class weights, label encoders — derive from Dtr only.
  • Validation, test and KDDTest-21 are transformed by the frozen training schema, so the evaluation distribution can never influence the representation.

Partitioning & imbalance

  • Official train/test boundaries are preserved where they exist; 15% validation is carved from the training partition.
  • Split-less datasets receive a seeded stratified 70/15/15 partition, stratified on the multi-class target so rare attack categories survive in every partition.
  • Exact duplicates are removed from training only — global de-duplication would change the natural validation and test distributions.
  • Balanced class weights are computed from the training target and used by Logistic Regression, Decision Tree, Random Forest, Linear SVM and the FT-Transformer. No synthetic over-sampling is introduced.
  • Test partitions are never touched during tuning or ensemble meta-training.

Evaluation metrics

Every metric is implemented in pure NumPy from one-vs-rest counts and cross-checked against scikit-learn to at least 1e-9 in the test suite.

macro-F1 · primary accuracy macro P / R weighted-F1 per-class P / R / F1 ROC-AUC PR-AUC (binary) OvR macro AUC confusion matrices fit / predict wall-clock serialised model size
Macro-F1 leads because it weights every class equally — the property that matters when rare attacks are the point. Aggregate scores give equal weight to each of the twelve dataset–task cases rather than pooling test records into a size-dominated statistic.
05 — Model suite

Seven base learners, two ensembles, one scratch build

The suite is deliberately heterogeneous: probabilistic and linear baselines, interpretable and ensemble tree methods, a margin-based classifier, two tabular neural architectures, and two score-level combiners. A method is informative even when it loses — its behaviour tells you whether the benchmark is approximately linear, whether feature interactions matter, and what computational price additional model complexity actually buys.

Base learners · mean test macro-F1 across 12 dataset–task cases

Score-level ensembles & the from-scratch implementation

Selection rule

  • Step 1 — standalone scratch target. The seven single base algorithms are ranked by equal-weight mean validation macro-F1 across the twelve dataset–task cases. Ensembles are excluded: the stack's meta-learner is fitted on validation score vectors, so its recorded validation metric is in-sample for the stacking layer.
  • Step 2 — final system comparison. With configurations fixed, standard-test macro-F1 is reported for all seven base algorithms and both ensembles — establishing the strongest predictive system without conflating a seven-estimator stack with one standalone algorithm.

Validation ranking that justified the scratch target

Random Forest leads the standalone validation comparison with mean macro-F1 0.867 and eleven wins out of twelve dataset–task cases — the evidence basis for re-implementing it from scratch.

When accuracy overstates capability

The single largest methodological finding: on multi-class UNSW and NF-v2 tasks, several models classify well over 90% of records correctly while performing poorly once every class is weighted equally. Dominant benign or high-volume attack classes carry the accuracy; rare-class failures stay visible only in macro-F1.

Read this as deployment retention, not estimator parity. The submitted configurations are not identical — the scratch forest grows 100 serial NumPy trees while the library forest grows 200 in parallel — and threshold enumeration, random-number streams and tie-breaking differ. Algorithmic parity is isolated separately by run_deploy.py compare, which trains both under aligned tree count, depth, leaf size, feature subsampling, class weighting and seed. On NSL-KDD binary that comparison reaches 98.8% prediction agreement with macro-F1 within 0.003; the synthetic parity test asserts >90% agreement and an absolute macro-F1 difference below 0.03.

One size-n sample drawn with replacement per tree

balanced_subsample, recomputed from each bootstrap's class frequencies

Mean leaf-probability distribution across trees, then argmax — a soft vote, not a vote over hard labels
Node storage
Flat parallel arrays: feature, threshold, left, right, leaf distribution

Compressed model.npz + JSON header — no pickle, deterministic reload
Importance
Split-frequency proxy, explicitly not impurity-decrease importance

Why the trade-off runs both ways

Rebuilding the algorithm changes its engineering profile more than its predictive behaviour. Serial NumPy training costs roughly 10.5× the median fit time and 16.4× the median prediction time of a mature parallel implementation. In the opposite direction, storing 100 trees as compressed arrays yields a median artefact about 2.65% the size of the library forest's — 4.40 MB against 166.34 MB, and 31.25 MB against 2.91 GB at the maximum.

Those ratios reflect both implementation and configuration, and should be read as observed deployment artefacts rather than a universal claim that a from-scratch forest is inherently 97% smaller.

Research questions, answered

RQ1 Which candidate strategy performs best? ▾
Stacked-LR has the highest equal-weight mean test macro-F1 at 0.824 and wins five of twelve cases. The library Random Forest is the strongest standalone base model at 0.818 with four wins. Stack when maximum portfolio-level performance is the priority; Random Forest when one independently deployable algorithm is required.
RQ2 How difficult is multi-class attack classification? ▾
Harder on five of six benchmarks. The best binary-to-multi macro-F1 gap reaches 0.391 on UNSW-NB15 and 0.320 on NF-UNSW-NB15-v2. NF-BoT-IoT-v2 is the exception at 0.013. Difficulty is greatest where several low-support attack classes must be separated from one another rather than merely from benign traffic.
RQ3 How robust are the models to KDDTest-21? ▾
The best binary macro-F1 falls from 0.787 to 0.539; the best multi-class result from 0.620 to 0.526. Rankings remain partly stable, absolute performance does not — stress evaluation should accompany conventional held-out testing whenever a benchmark supplies a harder distribution.
RQ4 Which standalone model balances performance and cost? ▾
Random Forest leads the standalone validation ranking (0.867, eleven of twelve wins) and remains the strongest base algorithm on the final test matrix, though its serialised footprint can be large. Decision Tree is faster and smaller at lower macro-F1; MLP is compact and competitive; the FT-Transformer is compact after training but carries the highest fitting cost under the fixed CPU configuration.
RQ5 How faithful is the scratch implementation? ▾
Mean test macro-F1 0.804, retaining 98.4% of the library forest's 0.818. Binary means are almost identical (0.930 vs 0.931); multi-class means differ more (0.678 vs 0.704). The median absolute case-level difference is only 0.0023, but NF-BoT-IoT-v2 and NF-CSE-CIC-IDS2018-v2 multi-class reveal larger losses — fidelity is strong overall, and not uniform across problem complexity.

Security implications

  • Balanced metrics are operational controls. Macro recall and confusion matrices expose the attacks that accuracy hides. A detector can classify most traffic correctly while missing a low-volume attack class entirely.
  • Score quality and threshold quality differ. High ROC-AUC signals strong ranking but does not guarantee the best macro-F1 at the default decision rule. Thresholds should reflect false-negative and false-positive costs.
  • Benchmark separability is not deployment proof. Near-perfect CIC-IDS2017 results have to be read against that dataset's scenario construction and documented data-quality history.
  • Feature leakage can imitate intelligence. Removing addresses, timestamps, flow identifiers and configured ports is what stops a model from learning a laboratory scenario instead of attack behaviour.
  • Transparent artefacts improve assurance. The scratch forest's JSON/NPZ representation, frozen schema, deterministic seed and explicit node arrays are all inspectable — there is no opaque pre-trained estimator object to trust.

Threats to validity

Internal

Random row splitting can still place related flows from one attack scenario into different partitions, particularly in CIC-style datasets, which may overstate within-benchmark generalisation. Training-only de-duplication substantially changes the fitted distribution for NF-BoT-IoT-v2 and NF-UNSW-NB15-v2 — the actual row counts are reported explicitly for that reason.

Construct

Macro-F1 is mathematically comparable across benchmarks, but a score on a four-category task is not semantically identical to the same score on a larger taxonomy. The scratch forest's split-frequency importance and the serialised-size comparison are useful operational evidence, not like-for-like algorithmic identities.

External

All six benchmarks originate from controlled, synthetic or reprocessed environments. They cannot fully represent production networks, encrypted application traffic, evolving attacks or adversaries adapting to the detector. NSL-KDD is especially old and the NF-v2 files are derivative representations. The results are comparative benchmark evidence, not guaranteed production detection rates.

Conclusion

Fixed reference hyperparameters improve consistency but may disadvantage models sensitive to regularisation, epoch count or depth. One deterministic seed is reported; the large test partitions reduce sampling noise, but repeated-seed intervals would give stronger evidence about ensemble variance and the scratch-versus-library comparison.

Repository, tests and reproduction

Roughly 5,600 lines of Python across four stages, with dataset-specific knowledge kept in YAML and a synthetic-fixture test suite that runs without a single byte of real benchmark data.

What the test suite guarantees

  • The cleaning quirks each dataset exhibits — repeated header rows, Infinity cells, missing-value markers, encoding faults, label-spelling drift.
  • Split stratification, and that no exact duplicate leaks from training into validation or test.
  • Schema JSON round-trips: fit → save → load → apply produces an identical matrix.
  • No-leakage guarantees, and that unseen categories at inference never change the feature dimension.
  • Metric equivalence with scikit-learn to at least 1e-9 across accuracy, macro/weighted P/R/F1 and AUC.
  • Ensemble construction, tuning behaviour and per-model training caps.
  • Scratch-forest determinism on save/reload, and synthetic parity against a library forest under aligned hyperparameters.

Tests requiring PyArrow or PyTorch skip cleanly when those packages are absent, so the suite passes on both a bare and a full install.

Recommended extensions

  • Repeat candidate and scratch experiments over multiple seeds and report confidence intervals.
  • Run aligned 100-tree and 200-tree library-versus-scratch comparisons on every dataset.
  • Introduce optional parallel tree construction while preserving deterministic per-tree seeds.
  • Optimise split search via pre-sorting, histogram thresholds or candidate-threshold sub-sampling.
  • Evaluate reduced-depth and reduced-tree-count scratch variants for latency-constrained deployment.
  • Perform day-aware or scenario-aware holdouts for CIC-IDS2017 and the NF-CSE derivatives.
  • Calibrate probabilities and optimise thresholds using explicit false-negative costs.
  • Evaluate the deployment bundle on a newly collected feature table transformed through the existing frozen schema.
